# A2 — Busca geoespacial perto do incidente

Incidente no Google Maps: `-25.4980, -48.5030` (lat, lon). No GeoJSON a ordem é invertida: **`[lon, lat]` = `[-48.5030, -25.4980]`**.

```js
db.movimentacoes.find({
  posicao: { $near: { $geometry: { type: "Point", coordinates: [-48.5030, -25.4980] }, $maxDistance: 300 } }
}).limit(10)
```
Script: [a2.js](a2.js) · saída: [a2_saida.txt](a2_saida.txt) · explain: [a2_explain.json](a2_explain.json)

## 1) Antes do índice 2dsphere

```
ERRO code 291 (NoQueryExecutionPlans): unable to find index for $geoNear query
```
O `$near` precisa de um índice geoespacial, e sem ele o MongoDB nem tenta: não existe "plano B" com COLLSCAN pra ordenar por distância.

Só pra comparar: um `$geoWithin` com `$centerSphere` (300 m / raio da Terra 6.378.100 m) até roda sem índice, mas faz **COLLSCAN em 400.000 docs (384 ms)**, devolve os 3.729 pontos do raio **sem ordem de distância**, e aí não dá pra pegar "os 10 mais próximos".

## 2) Índice criado
```js
db.movimentacoes.createIndex({ posicao: "2dsphere" }, { name: "idx_posicao_2dsphere" })
```

## 3) Depois do índice: explain executionStats

| stages | totalKeysExamined | totalDocsExamined | nReturned | executionTimeMillis |
|---|---|---|---|---|
| `LIMIT > GEO_NEAR_2DSPHERE > FETCH > IXSCAN` | 37 | 14 | 10 | 3 |

Lendo o plano de baixo pra cima:

1. **IXSCAN (idx_posicao_2dsphere)**: o índice 2dsphere guarda cada ponto como células S2 (a esfera dividida numa grade hierárquica). O Mongo calcula quais células cobrem o primeiro anel em volta do ponto e varre só essas faixas de chave: 37 chaves, 14 candidatos.
2. **FETCH**: busca os 14 documentos candidatos pra ter a coordenada exata (a célula é só uma aproximação).
3. **GEO_NEAR_2DSPHERE**: calcula a distância real de cada candidato, descarta quem passou do anel e coloca os outros num buffer ordenado por distância. A busca é por **anéis crescentes** (`searchIntervals`), e o primeiro anel (0 a 13,3 m) já teve 14 docs, o suficiente pra garantir os 10 mais próximos, então ele nem abriu o segundo anel. O `$maxDistance: 300` só seria o teto se faltassem pontos.
4. **LIMIT 10**: corta em 10. Não tem estágio SORT: a ordem por distância sai do próprio GEO_NEAR.

Ou seja, dos 3.729 pontos que existem no raio de 300 m, ele só olhou 14.
