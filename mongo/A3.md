# A3 — TTL que não apaga nada

Script: [a3.js](a3.js) · saída: [a3_saida.txt](a3_saida.txt)

## Prova no banco

```js
db.alertas.aggregate([{ $group: { _id: { $type: "$registrado_em" }, qtd: { $sum: 1 } } }])
```
```
{ "_id": "string", "qtd": 100000, "exemplo": "2026-06-04T16:33:04.971Z" }
```
**Todos os 100.000** alertas têm `registrado_em` como string. Nenhum é `date`.

O gerador não cria índice TTL nenhum (no início, `getIndexes()` mostrava só o `_id_`). Por isso criei o TTL do cenário, `{ registrado_em: 1 }` com `expireAfterSeconds: 2592000` (30 dias). Depois fiz um teste de controle: inseri dois alertas com a mesma data, de 60 dias atrás, um como `Date` e outro como string, e esperei o monitor TTL passar:

| | antes | depois de 2 passadas do TTL (90 s) |
|---|---|---|
| `metrics.ttl.passes` | 53 | 55 |
| total em `alertas` | 100.002 | **100.001** |
| controle com **Date** | existe | **apagado** |
| controle com **string** | existe | continua lá |

(O `metrics.ttl.deletedDocuments` foi de 17 pra 21, mas esse contador é do servidor inteiro: o TTL também apaga sessões expiradas em `config.system.sessions`. Na coleção `alertas`, a diferença foi de exatamente 1 documento.)

Ou seja, o TTL estava funcionando: apagou o único doc com Date vencido e ignorou os outros 100.001 com string, mesmo quase todos sendo de jan–out/2026, muito mais velhos que 30 dias. (Depois tirei o controle string pra coleção voltar a 100.000.)

## Causa raiz

O monitor TTL é uma thread do `mongod` que roda a cada ~60 s e apaga os docs em que o campo indexado é **BSON Date** (ou array com Dates) e `campo + expireAfterSeconds < agora`. Se o campo não é Date, o documento **nunca expira**, e o Mongo não avisa nem dá erro. O gerador grava com `new Date(...).toISOString()`, que transforma a data numa string ISO. Pra gente a string parece uma data, mas pro TTL é só texto.

## Correção

Índice TTL correto:
```js
db.alertas.createIndex({ registrado_em: 1 }, { expireAfterSeconds: 2592000 })
// se já existir um TTL nesse campo com outro tempo, ajusta sem recriar:
db.runCommand({ collMod: "alertas", index: { keyPattern: { registrado_em: 1 }, expireAfterSeconds: 2592000 } })
```

O ponto principal é a aplicação gravar o campo como **Date**:
```js
// errado: vira string e o TTL ignora
db.alertas.insertOne({ sensor: "S1", nivel: "aviso", registrado_em: new Date().toISOString() })
// certo: BSON Date
db.alertas.insertOne({ sensor: "S1", nivel: "aviso", registrado_em: new Date() })
```
(Em drivers: `new Date()` no Node, `datetime.now(timezone.utc)` no Python, `DateTime.UtcNow` no .NET. Nunca formatar pra texto antes de salvar.)

Os 100 mil antigos não foram migrados, como o enunciado permite. Daqui pra frente, os novos alertas gravados como Date vão expirar normalmente.
